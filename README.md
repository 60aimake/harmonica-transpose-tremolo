# 반주(MR) 변경툴 — 트레몰로

반주 음원을 **자르고 · 조(키)를 바꾸고 · 빠르기를 바꾸고 · 음량을 맞춥니다.** 설치할 것이 없습니다.

👉 **https://60aimake.github.io/harmonica-transpose-tremolo/**

`v1.3.0` · 2026-11-21

---

## 무엇이 되나

| | |
|---|---|
| **자르기** | 파형에서 시작과 끝을 끌어 쓸 데만 남깁니다. 고른 데만 미리 들어 볼 수 있습니다 |
| **조 바꾸기** | 반음 단위로 올리거나 내립니다. 빠르기는 그대로입니다 |
| **빠르기만 바꾸기** | 테이프를 빨리 감듯 바꿉니다. 음높이도 같이 바뀝니다 |
| **음량 맞추기** | 지금 음량을 재서 **−14 LUFS** 로 맞춥니다 |
| **내려받기** | 바꾼 소리를 MP3 또는 WAV 로 받습니다 |

```
「조만 바꾸기」는 원곡과 **길이가 같습니다.**
「빠르기 바꾸기」는 길이가 달라집니다.
무엇이 바뀌는지 화면에 적어 두었습니다.
```

---

## 쓰는 차례 — 여섯 단계

```
1. 갖고 있는 하모니카   한 번 고르면 다음부터 기억합니다
2. 반주 넣기            mp3 · wav · m4a · ogg
3. 자르기               ★ 안 하셔도 됩니다.  쓸 데만 남기고 싶을 때만
4. 지금 키 확인         도구가 찾아 줍니다.  틀리면 원에서 눌러 고칩니다
5. 할 수 있는 길        가진 하모니카로 갈 수 있는 조를 보여 줍니다
6. 받기                 파일 꼴 · 속도 · ★ 음량 을 고르고 「반주 바꾸기」
```

## 음량 맞추기 — 무엇을 하는 것인가

같은 반주들을 모아 놓으면 어떤 것은 크고 어떤 것은 작습니다.
이 도구는 **소리의 크기를 사람이 느끼는 대로 재서** 하나의 기준에 맞춥니다.

```
기준   −14 LUFS   방송·유튜브가 쓰는 값입니다
봉우리 −1.0 dBFS 를 넘지 않게 눌러 둡니다.  찌그러지지 않습니다
```

### 얼마나 정확한가 — 실측 (2026-11-21)

같은 음원을 ffmpeg(방송에서 쓰는 프로그램)과 이 도구로 각각 재 봤습니다.

```
음원 ①  ffmpeg −14.11  →  이 도구 −14.05
음원 ②  ffmpeg −13.60  →  이 도구 −13.57
음원 ③  ffmpeg −12.90  →  이 도구 −12.57
음원 ④  ffmpeg −13.97  →  이 도구 −13.88
★ 맞춘 뒤 내보낸 파일을 ffmpeg 으로 다시 재니 −14.09 였습니다
```

```
⚠️ 짧은 음원(20초 안팎)일수록 차이가 조금 커집니다.  0.4 LU 안쪽입니다
```

**파일이 기기 밖으로 나가지 않습니다.** 서버로 아무것도 보내지 않습니다.
브라우저 안에서만 소리를 바꿉니다.

## 속 — 바깥 라이브러리 0개

HTML 한 장입니다. 브라우저가 이미 가진 기능만 씁니다.

```
소리 읽기·쓰기   OfflineAudioContext · decodeAudioData · getChannelData
자르기           Float32Array.subarray — 복사를 안 해서 긴 곡도 바로 잘립니다
파형 그리기      canvas 2d — 한 픽셀마다 최대·최소를 찍습니다
조만 바꾸기      WSOLA  (창 2048 · 건너뜀 512 · 찾는 범위 256, 한 창 겹쳐 잇기)
빠르기 바꾸기    playbackRate
음량 재기        BS.1770-4 통합 라우드니스
                 K 가중 두 단계 → 400ms 블록(75% 겹침) → −70 LKFS · 상대 −10 LU 두 겹 거르기
                 계수는 표본율에 맞춰 그때그때 만듭니다
                 (48000 Hz 에서 규격 표와 소수 14자리까지 같은 것을 확인했습니다)
MP3 로 내보내기  lamejs 를 파일 안에 넣어 두었습니다
```
